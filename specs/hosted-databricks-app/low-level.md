# Hosted Databricks App — Low-Level Specification

## Module map

| Path | Responsibility |
| --- | --- |
| `src/haute/hosted.py` | The component. Detects the Databricks Apps environment contract, adapts platform-proxied traffic to the loopback shape the local security middleware expects, records the forwarded workspace user on the request scope, and builds the served ASGI application. |
| `databricks_app/app.py` | Container entry point: installs the locked runtime (`_install_locked_runtime`: the vendored wheel is checked against `wheel.sha256`, then `pip install --no-deps --require-hashes -r requirements.txt` and the wheel with `--no-deps --force-reinstall`, so nothing is resolved at boot), runs the boot probe, prepares the project, and serves `haute.hosted.create_app()` on the platform-assigned port. |
| `databricks_app/app.yaml` | Databricks App manifest defining the container command (`python app.py`) and environment configuration (session auth disable, state volume, and git credential settings). |
| `databricks_app/bootstrap.py` | Resolves the interpreter before changing directory, configures git credentials, restores a bound project (or seeds a volatile one), and `chdir`s into the project directory before the server is imported. |
| `databricks_app/probe.py` | One-shot boot diagnostics — interpreter, filesystem mounts, writability, git availability — printed as a HAUTE_DBX_PROBE-prefixed indented JSON blob into the platform log stream. |
| `databricks_app/requirements.txt` | Written by `build_bundle.sh`, never committed: the lock of haute's dependencies with the `[databricks]` extra, which the platform installs at deploy and the boot installs again. `uv pip compile` resolves it for the app's Python and platform, from wheels only (`--only-binary :all:`, as a deployment's lock, `haute.deploy._lock`), every distribution pinned by version and hash; its index lines are kept as comments with any credentials removed, since `--emit-index-url` writes a credentialed index URL as it is. |
| `databricks_app/wheel.sha256` | Written by `build_bundle.sh`, never committed: the vendored wheel's SHA-256 and file name, which the boot checks before installing it. |
| `databricks_app/scripts/build_bundle.sh` | Shell script that builds the wheel into a directory of its own and requires exactly one (a shared `dist/` can hold other versions), copies it into the app directory, enforces the 10 MB per-file limit, records its digest in `wheel.sha256`, and writes the lock as `requirements.txt`, for `HAUTE_APP_PYTHON` (default 3.11) on `HAUTE_APP_PLATFORM` (default `x86_64-manylinux_2_28`). |
| `databricks_app/scripts/deploy.sh` | Shell script taking the profile, workspace directory and app name: runs `build_bundle.sh`, syncs `databricks_app/` to the workspace, raw-imports the three gitignored build outputs after the sync (which honours `.gitignore` and may remove copies a previous deploy imported), and runs `databricks apps deploy` for the named app. |
| `databricks_app/LEARNINGS.md` | Operational deployment findings, platform traps (relative interpreter, absent container-shutdown signals), and two-actor live verification log for Databricks Apps. |
| `src/haute/_worker_isolation.py` | Owned by [execution-engine](../execution-engine/low-level.md); this component depends on its interpreter resolution. Owns worker spawning, including `ensure_spawnable_interpreter`, which absolutises a relative `sys.executable` before any directory change so `multiprocessing` can still exec it. |
| `src/haute/routes/databricks.py` | Owned by [databricks-io](../databricks-io/low-level.md); this component only adds the hosted credential shape. Workspace-browsing endpoints; resolves either a personal access token or the service-principal client id/secret the container injects. |

## Key types and data structures

- `DatabricksAppEnvironment` — frozen dataclass `{app_name, app_url, workspace_id}`, the detected platform contract.
- `DATABRICKS_APP_ENV_VARS` — the three variables that constitute that contract. All three present means hosted; none means local; a partial set is an environment this module was not designed for and raises rather than guessing.
- `FORWARDED_USER_SCOPE_KEY` — the ASGI scope key under which `PlatformProxyBoundary` records `X-Forwarded-Email`, read by request logging and by the storage bind and fork endpoints for attribution.
- `app_origin(app_url)` — the app's own origin, `(scheme, host, port)` through
  `src/haute/_local_security.py::web_origin`, raising `RuntimeError` naming
  `DATABRICKS_APP_URL` when the URL is not an `http`/`https` origin.
- `PlatformProxyBoundary` — an ASGI middleware wrapping the server application, built
  with that origin (`own_origin`, keyword-only, no default).

## Control flow

`create_app(project_dir)` requires a complete environment contract, then records the hosted trust decision by disabling the local session gate *before* importing `haute.server`, so the middleware stack initialises with that decision already in force. It builds the server application for the project in *project_dir*, the folder the bootstrap restored or seeded (`ProjectContext.at(project_dir)`: that folder itself, never the working directory), and returns it wrapped in `PlatformProxyBoundary`. The Databricks app's entry point passes the folder `bootstrap.ensure_project()` returns.

`create_app` reads `app_origin(environment.app_url)` before it records the trust decision, so a URL that is not an origin stops it before `haute.server` is imported, and builds the boundary with it.

For each HTTP or WebSocket scope, the boundary reads every `Origin` and `Sec-Fetch-Site` header as sent. A WebSocket scope, or an HTTP scope whose method is not `GET`, `HEAD` or `OPTIONS`, is another site's when any `Origin` is not the app's origin (`web_origin` of the header, decoded as Latin-1, differs, an unparsable or `null` one included) or any `Sec-Fetch-Site` is not `same-origin` or `none`; it is answered there and the server is never called: HTTP with `403` and `{"detail": "A change to this Haute app comes from the app's own page."}`, WebSocket with `websocket.close` code `1008` before accept, reason "Live sync connects from the app's own page.", and `cross_site_request_refused` logged at warning with the scope type, the method and the deciding header's name. Otherwise the boundary records `X-Forwarded-Email` (when present and non-blank, stripped of surrounding whitespace; blank or whitespace-only values are treated as absent) on the scope, strips `Forwarded` and every `X-Forwarded-*` header, replaces `Host` with the loopback authority of the bound server (`127.0.0.1:<port>`), and, when every `Origin` sent is the app's, replaces them with the one loopback origin `<scheme>://127.0.0.1:<port>`, the scheme `https` for an `https` or `wss` scope and `http` otherwise, as the local gate derives the request's; an Origin that is not the app's reaches the server as sent. Non-HTTP scopes (lifespan) pass through untouched.

## Edge cases and invariants

- A partial environment contract raises at startup; hosted mode is never inferred from one variable.
- `create_app()` outside a recognised hosted environment raises rather than silently degrading — hosting is an explicit deployment decision, and `haute serve` remains the local entry point.
- Header rewriting alone grants nothing: with the local session gate active, a proxied request whose headers now look local is still refused. Only the explicit hosted trust decision opens the API.
- The cross-site refusal does not depend on the session gate or on what the platform's sign-in cookie allows: it is decided from the request's own headers against the app's URL before any of them is rewritten. A navigation into the app from another site (a `GET`) is never refused by it.
- The forwarded-user scope key is absent rather than empty when the proxy sends no identity or a blank or whitespace-only `X-Forwarded-Email` header (and a non-blank value is stripped of surrounding whitespace), so consumers cannot mistake "no identity" for a blank user.
- Local mode is byte-identical: every behaviour here is gated on the environment contract.

## Error handling

Environment-contract failures raise `RuntimeError` at startup with the missing variables named — the container log is the only reader, so the message states what was set and what was not. Everything downstream keeps the server's existing error handling; the boundary adds no failure modes of its own.

## Testing

`tests/test_hosted.py` covers environment detection (absent, complete, each partial combination, whitespace-only values), the boundary's scope rewriting (forwarded metadata stripped, host rewritten to loopback, forwarded email recorded then removed, lifespan untouched), that stock haute still rejects proxied traffic, that `create_app` refuses outside a hosted environment and serves API and WebSocket traffic inside one, and — the security-relevant negative — that the boundary alone never bypasses the local session gate. `TestCrossSiteRefusal` drives the boundary with the hosted contract set: a `POST` with another site's Origin, an opaque `null` Origin, or `Sec-Fetch-Site: same-site` or `cross-site` is answered 403 without reaching the wrapped app or a route; a WebSocket handshake from another Origin is closed with 1008 before accept; the app's own page (its Origin, with `Sec-Fetch-Site: same-origin`) still posts to a route and opens `/ws/sync`, its Origin reaching the server as the loopback origin; a request with neither header and a cross-site `GET` pass; and a `DATABRICKS_APP_URL` with a path stops `create_app`. `tests/test_databricks_routes_auth.py` covers credential resolution for the workspace-browsing routes: personal-access-token precedence, the service-principal pair the container injects, and a missing-credential error that names both accepted forms without echoing a value. `tests/test_worker_isolation.py` covers `ensure_spawnable_interpreter`, including the relative-interpreter case this platform produces. `tests/test_secret_surface.py` is the structural backstop over both: it walks every registered response model for secret-shaped field names and scans `src/haute/` for references to secret-bearing environment variables, so a new credential surface — the platform injects one into every hosted container — cannot reach the API or a log without a reviewed allowlist entry. `tests/test_hosted_app_bundle.py` runs `build_bundle.sh` and `deploy.sh` under the bash a CI runner uses, with `uv` and `databricks` stood in by exported functions: the bundle holds the wheel just built beside stale ones in `dist/` (a newer build and a lower rebuild), a build making two wheels is refused, the lock is resolved for the app's Python and platform with the `databricks` extra, every pin carries its hash and no line keeps a credential, and the deploy imports the three outputs to the app it names; it also checks the outputs are gitignored and untracked, and that the boot installs the lock and then the checked wheel with `--no-deps`, refusing a wheel unlike its digest or a bundle without exactly one wheel before any install.

Known gaps: the platform proxy itself is simulated from its observed header set rather than exercised live; the live behaviour is recorded in `databricks_app/LEARNINGS.md`. The locked install was verified once by hand on 29 October 2026, not in CI (it downloads the whole closure): a bundle built on Windows installed on Linux CPython 3.11 with the boot's two commands, `pip check` found no broken requirements and the installed set was the lock plus haute. The boot does not run `pip check` itself: the platform pre-seeds its venv with framework packages haute never installs, whose requirements it cannot answer for.
