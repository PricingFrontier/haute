# Architecture roadmap - the engineering-marvel changes

> **Historical synthesis, not the active roadmap.** The

> Chief-architect synthesis of a 5-lens principal-engineer panel over the verified findings.

## Recommended order (severity x real-world urgency x effort)

1. **Deploy artifact identity** (roadmap #2 / cluster C4 + C3) - the only cluster that can mis-price a *live served quote* (validate loads a different model than the container serves); effort S. **Do first.**
2. **JSON-shred conservation + fingerprint completeness** (roadmap #3 / C2, C11, C12) - the cache spine; fail-loud-or-account at every loss boundary; effort S.
3. **Parser structure-conservation pass** (roadmap #4 / C5) - turns 7 silent node/submodel-loss bugs into one invariant; effort M.
4. **Chunk-sizing OOM fix** (roadmap #5 / C13) - cost row width from the target projected schema; memory safety; effort M.
5. **Codegen shared apply_*_from_config helper + parse->codegen->execute differential harness** (roadmap #1 / C1) - highest structural leverage, but standalone-.py portability only (deploy + in-canvas already run the executor and are safe); effort M.

Quick wins can land independently at any time.

## Top structural changes (5) - by structural leverage

### 1. Complete the shared `apply_*_from_config` runtime-helper pattern for EVERY stateful NodeType, enforce it as a registry invariant, and gate it with an execution-differential harness

- **What:** haute already proves the correct pattern for half its node types: banding/ratingStep/modelScore emit generated bodies that call ONE shared helper (`apply_banding_from_config`/`apply_rating_step_from_config`/`score_from_config`, re-exported from `graph_utils.py:36-41`) which the executor `_builders._build_*` also calls — so 'the pricing math has one implementation, not two'. The fix is to FINISH that pattern for the five types that abandoned it. Concretely: (1) Lift the node-application logic out of the executor closures into shared helpers in the graph_utils layer — move `_select_optimiser_apply_input`+`_dispatch_apply` (`_builders.py:1375-1429`) into `apply_optimiser_apply_from_config(first, *frames, config=, base_dir=, source=)`; add `select_live_switch_input(input_scenario_map, source, **frames)` (the executor's `switch_fn` logic at `_builders.py:640-666`); plus `expand_scenarios_from_config`, `apply_optimiser_from_config`, `apply_modelling_from_config`. Re-export each from `graph_utils.py` next to `apply_banding_from_config`. (2) Rewrite the five divergent templates in `_codegen_builders.py` — `_OPTIMISER`/`_OPTIMISER_APPLY`/`_MODELLING`/`_SCENARIO_EXPANDER` (currently literal `return {first}` via `_make_passthrough_builder`, lines 391-417) and `_LIVE_SWITCH` (currently hard-wires the live input, lines 268-273/521-539) — to the `_BANDING_SINGLE`/`_MODEL_SCORE` shape that imports and calls the helper, passing `config=config_path_for_node(...)` and `base_dir=Path(__file__).parent`. (3) liveSwitch threads the runtime source via `_scenario_ctx.get()` (the contextvar `Pipeline.run()` sets to 'batch' and `Pipeline.score()` to 'live' at `pipeline.py:329-411`) — so the generated body becomes branch-correct WITHOUT editing `Node.__call__` or `pipeline.py`. (4) Have the executor builders delegate to the same helpers so there is genuinely one code path. (5) Graft Lens-4's idea: extend `_registry.validate_registry_complete` (`_registry.py:166-188`) with a per-type `is_behavioural` flag so any non-structural-passthrough type whose codegen template emits a bare `return {first}` raises at import. (6) Add the differential-execution test the structural property test cannot do by construction: `tests/test_codegen_execution_equivalence.py` codegens a graph, writes sidecars, imports the file, runs `pipeline.run()`/`.score()` under source in {live,batch}, and frame-diffs against `execute_graph` for exactly the node types `ROUNDTRIPPABLE_NODE_TYPES` exercises only structurally. Key files: src/haute/graph_utils.py, src/haute/_builders.py (633-666, 999-1040, 1375-1429), src/haute/_codegen_builders.py (268-273, 391-417, 521-539, 784-857), src/haute/_registry.py (166-209), src/haute/codegen.py (delete the `_optimiser_apply_ratebook_return_source`/`_rewrite_single_return_source` string-surgery), NEW tests/test_codegen_execution_equivalence.py.
- **Why (leverage):** This is the single highest-leverage change and all five panels independently converged on it. The leverage is by-construction: when the generated standalone body and the executor builder are literally the same function, 'saved file prices identically to the canvas' is TRUE by construction rather than maintained in parallel — it cannot drift. The registry `is_behavioural` invariant makes the defect UNREPRESENTABLE: a future contributor physically cannot add a value-producing NodeType that ships a no-op body, because the package refuses to import. The differential harness makes it EXECUTABLE: it converts a class of bug that `ast.parse` accepts and prices wrong forever (in a saved file) into a red build. I verified the round-trip property test (`tests/test_codegen_roundtrip_property.py:662-672`) asserts only `_semantic_nodes`/`_semantic_edges` structural equality and never executes a body — a passthrough body round-trips its decorator+config perfectly while no-op'ing at runtime, which is precisely why this stayed latent. This is the executable enforcement of the README 'it's just Python, take it with you' promise.
- **Dissolves:** C1 in full (all 3 members: liveSwitch hard-wired branch, optimiserApply passthrough, optimiser/modelling/scenarioExpander no-op bodies). Structurally forecloses the entire recurrence class behind heat-map risk #1 — any FUTURE stateful NodeType silently shipping a passthrough/wrong-branch body — and removes the latent edge-join-role and rating-key wiring divergences from the same class since the body and executor share one wiring function. Retires `_make_passthrough_builder` and the bespoke codegen string-rewrite helpers as dead code. The differential harness also catches the detection-class for C5 (a dropped node changes executed output even when structural diffing is fooled).
- **Effort:** M
- **Risks:** Medium. (a) The optimiserApply helper must resolve the ratebook frame from config-derived selection (connected-input ORDER), not live canvas `source_ids`, so a standalone file with no `source_ids` still picks the right frame — mitigate by threading the ordering through the sidecar/decorator and keeping the lift mechanical (move `_select_optimiser_apply_input` verbatim, don't rewrite). (b) liveSwitch's generated body shape genuinely changes (it now reads the runtime source) — the differential harness under BOTH sources is the guard; pin the executor's existing optimiserApply/liveSwitch tests green BEFORE switching templates so the extraction is a proven pure refactor. (c) The `is_behavioural` invariant must allowlist genuine structural passthroughs (output/dataSink) to avoid false import-time failures — drive it off an explicit registry field, not heuristic body inspection.

### 2. Make artifact identity a first-class input: ONE `artifact_identity_fingerprint` helper threaded through the deploy validate path AND every output-affecting cache key

- **What:** C3 and C4 are the same structural gap on the only HIGH findings that touch DEPLOYED/served prices, seen from two sides. I verified: `score_test_quotes` (`deploy/_validators.py:375-380`) and `infer_output_schema` (`deploy/_schema.py:134-139`) both call `score_graph(...)` WITHOUT `artifact_paths`, even though `score_graph` accepts it and the container DOES pass `artifact_paths=_artifact_paths` (`deploy/_container.py:394,407`) — so the 'test before live' gate loads a model live from MLflow ('latest', mutable) that can differ from the bundled bytes the container serves, and skips the contract check; and `infer_output_schema` keys its `.haute_cache/output_schema.json` on `graph_fingerprint(graph, output_node_id, *input_node_ids)` ALONE (`_schema.py:95`), which excludes model-artifact bytes/version, so a retrained in-place 'latest' artifact bakes a stale ModelSignature/manifest. The fix is ONE rule applied via ONE helper: add `artifact_identity_fingerprint(resolved.artifacts)` (a thin wrapper over the existing `haute.execution._stat_gated_runtime_path_fingerprint`, already used at `deploy/_scorer.py:199`), then thread `resolved.artifacts` into BOTH (a) `score_graph(..., artifact_paths=...)` and (b) the cache key, in ONE pass through `deploy/_schema.py` so the file is touched once. Concretely: pass `artifact_paths={n: str(p) for n,p in resolved.artifacts.items()}` at both validate call sites; give `infer_output_schema` an `artifact_paths` param and compute `fp = graph_fingerprint(...) + ':' + artifact_identity_fingerprint(...)` (or, simpler per the cluster, skip the output-schema cache for graphs containing modelScore/optimiserApply); update the `_config.py:575` caller to pass `resolved.artifacts`. Fold in C3's two sibling members the same way: resolve the preamble utility via `importlib.util.find_spec` under exec-time sys.path and hash `spec.origin` into `preamble_execution_fingerprint` (`_cache.py`); drop `id(scoring_model)` from the feature-validation key (`_model_scorer.py`) and rely on contract+schema. Add a regression test asserting validate and serve load BYTE-IDENTICAL artifacts (hash the resolved bytes each path loads) and that retraining 'latest' in place changes the output-schema key. Key files: src/haute/deploy/_validators.py (339-405), src/haute/deploy/_schema.py (74-150), src/haute/deploy/_config.py (~575), src/haute/execution.py (reuse `_stat_gated_runtime_path_fingerprint`), src/haute/_cache.py (371-397), src/haute/_model_scorer.py.
- **Why (leverage):** This is the most URGENT real-world change: it is the only cluster pair that can mis-price a LIVE served quote (validate green on a different model than the container runs) or bake a stale signature into the deployed manifest. The leverage is that artifact identity becomes a REQUIRED input to both validation and freshness rather than an optional kwarg a caller can forget — making 'validate exercises the exact bundled bytes the container serves' and 'a retrained artifact invalidates the cached schema' true by the same construction. `resolved.artifacts` is already available at every call site (it is literally what the container uses), so this is wiring + a required-argument tightening, not new logic — exceptionally high leverage per line. It is the existing fingerprint-COMPLETENESS dossier applied to the one input class the keys currently miss.
- **Dissolves:** C4 in full (validate-vs-serve artifact divergence + skipped contract check) and the model-artifact member of C3 (stale baked output schema/manifest). Generalizes to the preamble-module and feature-validation members of C3 via the same 'fold the missing input class into the key' move. Eliminates heat-map #9's deploy validate-vs-serve silent dev-vs-prod mispricing as a CLASS. Pairs structurally with rank 3 (both enforce fingerprint-completeness).
- **Effort:** S
- **Risks:** Low. Folding artifact bytes into the output-schema key means a retrained model now (correctly) invalidates the cached schema — intended, but it changes cache-hit rate; mitigate by reusing the stat-gated fingerprint so UNCHANGED artifacts stay cheap, or take the cluster's simpler option (skip the cache entirely for modelScore/optimiserApply graphs — fewer moving parts). The find_spec preamble resolution must run under the same exec-time sys.path the preview/trace uses. Slight risk a validate-time fixture relied on the implicit 'latest' load — but that reliance IS the bug; the byte-identical regression test pins it.

### 3. Encode JSON-shred conservation + fingerprint-completeness as a CHECKED invariant in the wave-2 cache spine (fail-loud-or-account at every loss boundary)

- **What:** C2 is the named wave-2-cache-integrity mandate, and its members are one defect in different cells of one walker. I verified `_v2_fingerprint` (`_json_shred.py:108-147`) `continue`s past non-dict tables (line 118) and non-dict columns (line 122) with no accounting — so two structurally-different on-disk configs collapse to one `schema_fingerprint` and a stale per-port parquet cache is judged fresh; `_resolve_leaf` collapses a mid-walk list to element [0]; `shred_to_buffers._walk` flattens a nested list inside a scalar array, inflating rows past source-element count with zero skip accounting; and the status route reads the v2 config WITHOUT `validate_v2_schema`. The codebase ALREADY built the right machinery — `ShredSkipStats` with `count_record_skip`/`count_row_skip` surfaced in meta.json — but applies it unevenly (the fingerprint path bypasses it entirely). The fix makes conservation a CHECKED invariant, grafting Lens-1's framing: (1) in `_v2_fingerprint`, replace the two `continue`s with `raise ApiInputSchemaError(...)` (callers validate first, so this only fires on a genuinely malformed on-disk config and routes to the existing 422 path) so distinct configs can never collapse to one fingerprint; (2) in `_resolve_leaf` and `_walk`, route every mid-walk-list collapse / nested-list flatten through `count_*_skip` (or raise) so emitted rows reconcile to source; (3) in `build_per_port_cache`, ADD a reconciliation assertion that every DROP and COLLAPSE is accounted (NOT rows==records — an array of N objects correctly emits N rows), failing the build (the atomic temp-dir already rolls back) on unaccounted loss; (4) call `validate_v2_schema(v2_config)` inside `_v2_status_response` before `is_per_port_cache_valid` (mirroring `build_per_port_cache`), letting `ApiInputSchemaError` hit the existing 422; (5) close the data-file freshness hole in `_data_file_matches` (`_json_shred.py:253-271`) — the stat fast-path returns fresh on size+mtime_ns match, so a byte-changing rewrite preserving both serves stale; either drop the mtime fast-path and always verify sha256, or keep stat as a hint and verify the hash on match. Pin each with a failing collision/conservation/freshness test FIRST. Key files: src/haute/_json_shred.py (108-147, 253-271, 509-536, 597-652), src/haute/routes/json_cache.py.
- **Why (leverage):** This IS the wave-2 mandate (heat-map #2) and contains a HIGH (nested-list row inflation) plus collision/stale-freshness items that serve stale cache AS fresh — a silent-wrongness class on the cache spine the branch is named for. The leverage: encoding 'no silent loss + fingerprint completeness' as a build-time RECONCILIATION CHECK means a future walker edit that re-introduces silent loss fails a test instead of shipping — it converts a per-site whack-a-mole into one enforced property. High leverage per edit (single file + one route call). It also sets the codebase-wide 'fail-loud-or-account at every loss boundary' discipline that rank 4 (parser) and the trace de-laundering follow.
- **Dissolves:** C2 in full (fingerprint collision on non-dict tables/columns, nested-list row inflation, mid-walk-list collapse, the status/validity schema-validation gap, and the data-file stat-gate). Naturally batches with C11 (committed-mirror lock/ns-precision/Windows-safe-rename — same `_json_shred.py`, reuse the sibling `_swap_dir_into_place` machinery) and C12 (cache-build vs parser duplicate-key divergence + the `store_artifact` over-eager revalidation-evict — same `json_cache.py`). Generalizes the conservation discipline to the C5 parser cluster.
- **Effort:** S
- **Risks:** Low-to-medium. The reconciliation assertion needs a precise definition of 'expected rows' — a legitimately-repeated array of N objects SHOULD emit N rows (correct multiplication, not loss), so the invariant is 'every DROP and every COLLAPSE is counted', not 'rows==records'; get this wrong and it false-positives. The fingerprint raise turns a previously-silent acceptance into a 422 for genuinely-malformed configs — desired per fail-loud, but pin with a test that a hand-corrupted config now raises rather than collides. Always-hash data-file matching is the one real perf cost — the stat-gate-as-hint-then-verify variant keeps the fast path while closing the byte-preserving-rewrite hole.

### 4. Add a parse-time STRUCTURE-CONSERVATION pass that proves every authored node/edge/submodel survives into the graph (or raises) — fail-loud by construction, not per-shape

- **What:** C5's seven members are one class: the parser drops or collapses authored graph structure at many independent boundaries WITHOUT a loud error, violating the CLAUDE.md fail-loud mandate. Today each is a separate silent gap to patch individually and re-introducible. The structural change is a single post-parse `assert_structure_conserved(source, graph)` the parser ALWAYS runs: AST-walk the main file for decorated `FunctionDef`+`AsyncFunctionDef`, regex-scan top-level `pipeline.submodel("...")` literals (recoverable the same way the healthy path scans them), and collect `connect()`/param-name edges; then assert each authored function name is unique (raise ParseError naming duplicates — fixing the silent duplicate-name collapse in `_ast_helpers._extract_function_bodies`), each maps to exactly one GraphNode, each submodel reference resolves to a distinct pipeline_name (raise ConfigError naming both files on collision), and each authored edge is present — against an explicit allowlist of 'authored element -> expected graph element(s)' so legitimate structural transforms (submodel placeholders, output/dataSink) are not false-positives. Under the same umbrella, fix the two members that need a specific behaviour rather than just a loud assert: (a) the regex fallback parser — replicate the healthy path's submodel recovery (regex-scan `submodel()` literals, resolve via `resolve_submodel_reference`, parse each) so a broken main file no longer NULLS all submodels (scope the fallback's parsing to the submodel literals only, so it does not itself raise on the syntax error that triggered the fallback); (b) async def — raise a clear unsupported-async ParseError (or broaden to AsyncFunctionDef) per chosen policy; plus retain child `param_names` through `merge_submodels` to reconstruct the dropped implicit cross-boundary edge, a graph-level `logger.warning` for the 1-level nested-submodel cap, and AST/alias-aware preamble boundary detection so an aliased `import haute as h` construction line is not double-captured. Each gated by a failing test first. Key files: src/haute/parser.py, src/haute/_ast_helpers.py, src/haute/_parser_regex.py, src/haute/_parser_submodels.py, src/haute/_graph_builders.py, src/haute/_cache.py.
- **Why (leverage):** This is the parser arm of the cross-cutting fail-loud discipline (the same one ranks 1, 3 enforce elsewhere). The leverage: it converts 'silent loss at shape X' from a whack-a-mole of seven independent per-site patches into ONE invariant check, so a future parser change that loses structure fails the conservation assertion instead of shipping a graph that silently drops a node's pricing body. The regex-fallback member is itself a HIGH (a single syntax error in the main file silently discards ALL submodels and their nodes/edges, degrading the GUI graph). Directly enforces the CLAUDE.md fail-loud principle on heat-map #5.
- **Dissolves:** C5 in full (all 7 members: regex-fallback submodel discard, duplicate-name collapse, async-def invisibility, implicit cross-boundary edge drop, submodel name-collision overwrite, nested-submodel silent ignore, aliased-import preamble over-capture). The conservation pass catches the structural ones loudly; the regex-recovery + alias-aware detection + param_names threading close the ones needing a specific fix.
- **Effort:** M
- **Risks:** Medium. The conservation pass must distinguish a LEGITIMATE structural transform (a submodel placeholder intentionally absent as a root node) from a genuine loss — needs the explicit authored->expected allowlist, not naive count-equality, or it false-positives on valid graphs. The async-def and duplicate-name policies are product decisions (raise vs support) — pick raise for both to stay strictly fail-loud, pin each with a failing test first. The regex-fallback recovery must NOT raise on the very syntax error that triggered the fallback — scope its parsing to the submodel literals only.

### 5. Cost byte-budget chunk sizing from the TARGET node's projected output schema, not the source schema (close the OOM under-bound)

- **What:** C13 is a HIGH OOM hazard on the wave-2 execution surface. I verified the precise mechanism: in `chunking.py`, `_plan_chunk_sizes` (line 593) sizes the chunk from `target_row_bytes = _estimate_projected_row_bytes(target_columns, source_node=..., target_node_id=...)` (line 609), and `_estimate_projected_row_bytes` (line 629) only obtains real widths via `_source_projected_column_widths(source_node, projected_columns)` (line 643) — which RETURNS `{}` for any node whose type is not `DATA_SOURCE` (line 658-659). So for the TARGET node's columns, every downstream-created wide/string column that does not exist on the source falls back to `_DEFAULT_PROJECTED_COLUMN_BYTES` (~64 bytes), and the computed chunk can far exceed the memory budget → OOM. The fix: cost the target row width from the TARGET node's PROJECTED OUTPUT schema — `collect_schema()` on the target lazyframe restricted to `needed_by_node[target]`, sampling String/variable-width columns the way `_source_projected_column_widths` already samples the source (lines 661-687), instead of reading the source schema for target columns. Prioritise this chunk-sizing fix (the HIGH). Treat the second C13 member — the `ExecutionContext` memory limit being a coarse gate sampled only at checkpoint/stage boundaries, so a single ballooning collect/sink between checkpoints is never interrupted — as LOWER priority (L effort): optionally add a bounded-interval watchdog thread per `ExecutionContext` that polls `memory_sampler()` and trips the cancellation token, noting it cannot pre-empt a single in-flight Polars C++ collect (so pair with a hard `process_rss_limit` if pursued). Key files: src/haute/chunking.py (593-687), src/haute/_execution_context.py.
- **Why (leverage):** It is a real OOM (process-killing) hazard with a precise, contained root cause: the chunk planner reasons about the wrong/too-coarse row width for exactly the columns most likely to blow the budget (downstream-created wide strings). The leverage is making memory admission reason about the ACTUAL bytes the target stage materialises, so the budget the planner enforces matches reality — turning a silent OOM under load into a correctly-sized chunk. Self-contained on the wave-2 chunking surface the branch already owns.
- **Dissolves:** The HIGH chunk-sizing member of C13 (source-schema-only width estimation under-bounding downstream wide/string columns). The continuous-memory-enforcement member is explicitly deferred as lower-priority L-effort, not dissolved here.
- **Effort:** M
- **Risks:** Medium. `collect_schema()` on the target lazyframe must not trigger expensive computation — keep it to schema resolution + a bounded width sample (reuse the existing `_ROW_BYTE_SAMPLE_SIZE` path), and preserve the existing `ChunkPlanUnsupportedError` fail-loud behaviour when the schema can't be inspected (do NOT add a silent fallback — a wrong width is the bug being fixed). Gate with a test that constructs a transform creating a wide string column absent from the source and asserts the planned chunk respects the byte budget.

## Quick wins

- **Thread `resolved.artifacts` into the deploy validate call sites (the C4 half of rank 2)** - Closes the only live-served-price divergence (validate loads a different/newer model than the container serves) with a near-trivial wiring change. Highest value-to-effort ratio in the whole backlog; no branch overlap.
- **Dedup the four drifted job-failure-mapping ladders in `_optimiser_service.py` into one handler** - The copies have ALREADY drifted (heat-map #4 / open-question #12 answered 'no, not in sync'). Centralising kills the 'fixed in one copy, not the others' class AND makes the C15 error-flip-omits-terminal_reason impossible (all error transitions go through one mapper that always sets it). Pure behaviour-preserving dedup of already-tested branches; ~200 lines removed.
- **Remove the value-laundering catch-alls on the trace display path (C7)** - Display-only (never corrupts a stored price) but a direct fail-loud violation: a self-consistent-looking waterfall currently masks evaluator bugs by substituting the input for the output. Cleanest fail-loud win in the codebase; answers architecture open-question #8 ('does any test assert a systematic evaluator bug surfaces loudly?' — currently no).
- **Swap the unbounded sandbox `_validation_cache` dict for the existing bounded `LRUCache` (C19)** - Trivial swap to an existing helper that closes a slow memory growth on long-running servers; matches the codebase's own bounded-LRU pattern.
- **Flip the executor's path resolution to `enforce_project_root=True` (the silent-wrong member of C18)** - The only silent-wrong-adjacent member of C18 (arbitrary read), and a cheap, principled boundary fix; coordinates naturally with the rank-3 json_cache.py batch. Single-user local engine bounds the exposure, but the execution-boundary fix is correct and near-free.
