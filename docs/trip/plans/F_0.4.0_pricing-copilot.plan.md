# Pricing Copilot Implementation Plan

**Proposed version: 0.4.0** (minor bump from 0.3.4 — a new, additive, backward-compatible feature).

## Overview

An in-app AI copilot: a chat panel in the Haute GUI where a pricing analyst instructs an
LLM agent to author the pipeline graph. A backend-owned agent loop (pluggable providers —
Anthropic and OpenAI first; a Databricks-hosted endpoint later is the OpenAI adapter plus a
`base_url`) executes graph-authoring tools whose mutations land through the existing
transactional save service and broadcast over the existing `/ws/sync` channel, so every
canvas updates live as the agent works. v1 scope is graph authoring only — no execution,
training, optimisation, deploy, or git tools.

## Design

The design lives in the component specs, updated on this branch
(`git diff HEAD --stat -- docs/specs/` shows the deltas):

- `docs/specs/copilot/` *(new pair)* — the backend: agent loop, provider adapters, tool
  surface and ops engine (incl. `get_node_schema` via the execution engine), the packaged
  knowledge assets (authoring guide + engine-parsed exemplar pipelines), sessions, SSE
  streaming, configuration/readiness, failure model.
- `docs/specs/frontend-copilot-ui/` *(new pair)* — the chat panel: transcript/composer,
  store-owned stream consumption, send gates (clean canvas, readiness, one-turn lock),
  stop/new-chat semantics.
- `docs/specs/server-api/` — copilot router ownership boundary, router registration, the
  `Copilot*` schemas' home, and the copilot's consumption of the save service, `save_lock`,
  self-write marking, and the `graph.update` event bus.
- `docs/specs/frontend-shared/` — `api/copilot.ts` joins the bundle-split endpoint-module
  precedent; `useUIStore` gains the mutually-exclusive `copilotOpen` flag.
- `docs/specs/frontend-graph-canvas/` — reverse interaction: copilot edits arrive as
  ordinary `graph.update` frames (unchanged apply/rollback/dirty-gating); the copilot panel
  reads the derived dirty state.
- `docs/specs/frontend-node-editors/` — reverse interaction: the copilot panel renders in
  the shared `PanelShell`/`PanelHeader` chrome and follows the lazy-loading convention.
- `docs/specs/README.md` — component-index rows for the two new components.

## Performance & Cost Impact

- **No performance-sensitive execution path is touched** — executor, projection, preview,
  and trace are unchanged; the perf suite is unaffected. The one save-path edit is the
  `save_graph_transactionally` explicit field forward (item 14) — no behavioural cost.
  An idle copilot costs nothing at runtime (no polling, no background work; import-time
  catalog validation is trivial).
- **Per turn**: provider token cost on the user's own key; each mutation is exactly one
  ordinary transactional save plus one event-bus publish — identical cost profile to a GUI
  save; one open SSE connection per active turn, bounded by the one-turn-per-session lock.
  `get_node_schema` builds a lazy plan and reads its schema — no data collection (the
  collect-poisoning test enforces this); the authoring guide and exemplar index add a
  small, fixed system-prompt token overhead, with full exemplars fetched only on demand.
- **Frontend**: the panel, its store consumers, and the markdown renderer live in a lazy
  chunk; the initial-bundle gate (`scripts/check-bundle-size.mjs`) stays green with one
  documented +1 KiB budget ratchet (244 → 245 KiB) for the deliberate eager surface — the
  always-visible Toolbar toggle and the `postRawStream` client helper — following the
  gate's existing per-feature ratchet convention; everything else is lazy, enforced by
  `App.copilotLazy.test.ts`.

## Backward Compatibility

- Routes are additive; no existing response model changes (new `Copilot*` schemas only), so
  the UI-contract golden tests are untouched.
- `haute.toml` without a `[copilot]` table is the ordinary not-configured state; existing
  projects parse, run, save, and deploy exactly as before.
- The default `pip install haute` is unchanged — LLM SDKs arrive only via the opt-in
  `haute[copilot]` extra.
- No pipeline file format, sidecar, or codegen changes; nothing to migrate.

## Test Impact

- **New backend suites** (item 28) per `docs/specs/copilot/low-level.md` § Testing. The ops
  engine, provider adapters, and agent loop are silent-wrongness classes — build them
  **test-first** (TDD per CLAUDE.md): op semantics/atomicity (incl. batch-local `$ref`
  resolution and post-batch positions), stream normalisation, the exactly-one-terminal-event
  and cancellation-shielding invariants, `save_lock` critical-section exclusivity, the
  working-branch mutation precondition, and preserve-marker round-tripping (with the
  `save_graph_transactionally` seam regression in the existing save-service suites).
- **Knowledge assets and the schema tool** (items 4–5, 7) carry their own guards:
  `tests/test_copilot_assets.py` parses every packaged exemplar through the real engine (a
  stale exemplar fails CI, like a stale catalog entry) and asserts the guide loads
  non-empty; `tests/test_copilot_tools.py` covers `get_node_schema` including the
  collect-poisoning invariant (schema resolution must never invoke `LazyFrame.collect`).
- **New frontend suites** (item 29) per `docs/specs/frontend-copilot-ui/low-level.md`
  § Testing; the SSE parser and store state machine are **test-first**; the lazy-import
  guard mirrors the existing `NodePanel.lazyEditors` pattern.
- **Existing guard suites sweep the new code automatically** and must pass unmodified:
  `test_routes_hygiene.py` (new route module), `test_decoupling_contracts.py` (no `print`,
  structlog), coverage's global 90%-branch gate (new package included),
  `test_docs_accuracy.py` (unaffected — its enforced "21 node types" sentence and tables
  were deliberately not disturbed).
- **Integration/E2E**: `tests/test_copilot_integration.py` runs a scripted fake provider
  against a real tmp project — asserting on-disk codegen/sidecar state and the published
  `graph.update` payload; a manual real-key smoke via `haute serve` is a release-notes step,
  not CI.

### Post-review addendum (2026-07-19, live smoke testing)

User-driven changes made after the Codex review synthesis, during live manual smoke testing
against Databricks serving endpoints (all TDD-first, each with its own reviewer pass or
batch verification; specs updated in lockstep):

- **Product rename: "copilot" → "Assistant"** (user decision). Full rename — package
  `haute.assistant`, routes `/api/assistant/*`, `[assistant]` config table,
  `HAUTE_ASSISTANT_MAX_OUTPUT_TOKENS`, `Assistant*` schemas/stores/components, pyproject
  extra `haute[assistant]`, spec dirs `docs/specs/assistant/` +
  `docs/specs/frontend-assistant-ui/`. This plan file keeps its historical name.
- **OpenAI adapter dialect fixes** (captured live from Databricks): content-part lists
  (`text`/`reasoning` parts) accepted alongside plain-string deltas; end-of-stream contract
  tolerates Databricks' intermittently-omitted `finish_reason` only under strict guards
  (text streamed, usage observed, under budget, no pending tool call) with typed
  `truncated`/`malformed_stream` failures otherwise; debug-level `*_chunk_shape` wire
  logging; server-side `*_provider_request_failed` diagnostics.
- **`list_datasets` navigability**: per-directory listing now names visible subdirectories;
  POSIX-normalised model-facing paths.
- **Core parser fix (out of feature scope, user-approved)**: removed the definition-order
  edge-invention fallbacks in `_build_edges` and `Pipeline.to_graph()` — edges are never
  invented; disconnected graphs are representable (see `pipeline-config` specs).
- **Persistent chat sessions** (user decision): the server is a locally-run distribution
  vehicle restarted constantly, so committed turns write through to
  `.haute/assistant/sessions/<id>.json` (untracked, gitignore-guarded `.haute/`; `_git_state`
  corrupt-file posture; atomic writes). `POST /session` accepts a resume `session_id` and
  returns a rehydratable transcript; the frontend remembers session ids in `localStorage`
  per pipeline and rehydrates on resume. New suites:
  `tests/test_assistant_session_persistence.py`, `TestSessionResume` in the routes tests,
  and store/api persistence tests.
- **Assistant ships in core** (user decision): `anthropic`/`openai` moved from the
  `haute[assistant]` extra into core dependencies; the extra was removed pre-release and
  the missing-SDK readiness reason now names a broken installation.
