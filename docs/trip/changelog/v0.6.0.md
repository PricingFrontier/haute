# Changelog - V. 0.6.0

## Migration note

- Pipeline execution now uses one bounded strategy contract across preview,
  training, optimiser, sink, deploy, and trace surfaces. Diagnostics expose
  projection provenance, streamability evidence, column widths, counters, and
  memory observations without treating unavailable measurements as zero.
- Unsafe ambiguity now fails loudly. Unsupported group-by execution, trace
  correlation dtypes, missing rating factors, undefined all-null rating extrema,
  unmapped live-switch scenarios, and null OUTPUT nesting keys return structured
  HTTP 422 payloads; background work records the same stable error code and
  fields with terminal reason `contract_error`.
- Preview and trace caches now use lineage-scoped, byte-bounded multi-entry
  identity. Changes to relevant inputs invalidate the affected lineage, while
  disconnected or downstream-only edits no longer discard reusable upstream
  results.
- The internal in-memory `COLLECT_LAZY` checkpoint action was removed. Explicit
  materialisation boundaries must pass the active execution profile and memory
  admission checks.
- `haute._polars_utils.best_effort_sink` and `safe_sink` have been removed.
  Batch writers must use `bounded_sink`; callers that require eager
  materialisation must make that boundary explicit in their own workflow.
