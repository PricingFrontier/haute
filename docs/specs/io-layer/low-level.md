# IO Layer — Low-Level Specification

## Module map

| File | Responsibility |
|---|---|
| `src/haute/_io.py` | Legacy `dataSource` flat-file read path (`read_source`, `read_data_source`, `DataSourceAdapter`), shared path/schema/column validation helpers, and `load_external_object` for non-tabular files. |
| `src/haute/_polars_io_registry.py` | Format registry (`FORMATS`/`IoFormat`) for `dataInput`/`dataOutput` nodes: format/mode resolution, argument allow-listing, invocation (`read_polars_input`, `write_polars_output`), and the sidecar-config entry points generated code calls. |

| `src/haute/_path_case_audit.py` | `case_equivalent_siblings`/`warn_if_case_ambiguous`/`wrap_path_case_audit` — cross-platform case-ambiguity detection for user-facing paths. |

| `src/haute/_polars_utils.py` | `streaming_collect`, `bounded_collect_batches`, `bounded_sink`, `best_effort_sink`/`safe_sink`, `atomic_write`, `read_parquet_metadata`, `temporary_streaming_chunk_size`, `_malloc_trim`. |

## Key types and data structures

- `SourceFormat(StrEnum)` (`_io.py`) — `CSV`/`JSON`/`NDJSON`/`PARQUET`; the
  dispatch key for `read_source`.
- `DataSourceAdapter` (`_io.py`, frozen `slots` dataclass) — `source_type`,
  `location`, and a private `_reader` callable of shape `(profile, columns,
  validate_columns) -> LazyFrame`. `.read()` normalises `columns`/
  `validate_columns` via `_normalise_columns` before delegating.
- `IoFormat` (`_polars_io_registry.py`, frozen `slots` dataclass) — one
  format's full capability record: `name`, `label`, `source_kind`
  (`"path" | "database" | "inline"`), `reader`/`scanner`/`writer`/`sinker`
  (polars callable names, `None` when that operation doesn't exist),
  `extensions` (advisory only), `bounded_read`, `needs_schema_when_bounded`,
  `unstable`, `read_engines`/`write_engines` (import names — any one
  importable satisfies the requirement), `source_owned_args` (config keys
  that are node fields, not `arguments` entries).
- `FORMATS: tuple[IoFormat, ...]` / `FORMATS_BY_NAME: dict[str, IoFormat]`
  (`_polars_io_registry.py`) — the registry; 14 formats as of this writing
  (csv, json, ndjson, parquet, ipc, ipc_stream, avro, excel, ods, lines,
  database, delta, iceberg, records).
- `PolarsIoConfigError(ValueError)` (`_polars_io_registry.py`) — every
  registry-level config problem.
- `SourceKind = Literal["path", "database", "inline"]`,
  `InputMode = Literal["read", "scan"]`, `OutputMode = Literal["write",
  "sink"]` (`_polars_io_registry.py`).
- `REMOTE_IO_ARGUMENTS`, `_OBJECT_VALUED_ARGUMENTS`,
  `_SINK_EXECUTION_OWNED`, `_DTYPE_MAPPING_ARGUMENTS`
  (`_polars_io_registry.py`, module-level `frozenset`s) — the argument-name
  exclusion/decoding classes `allowed_arguments`/`validate_arguments` apply.
- `_polars_io_arguments.json` shape: `{polars_version, python_version,
  extracted_at, function_count, functions: [{name, owner, qualified_name,
  kind, doc_has_parameters_section, arguments: [{name, kind, position,
  annotation, has_default, default, undocumented}], return_annotation}]}`.
  `io_functions_by_key()` indexes `functions` by `f"{owner}.{name}"`
  (e.g. `"polars.read_csv"`, `"LazyFrame.sink_parquet"`).
- Dtype spec grammar (`_polars_dtypes.py` module docstring) — each spec is
  either a scalar string (`"int64"`, `"str"`, alias table
  `POLARS_DTYPE_ALIASES`, or any `pl.*` attribute name) or an object with a
  `"type"` key: `List{inner}`, `Array{inner,size}`, `Struct{fields}`,
  `Decimal{precision,scale}`, `Datetime{time_unit,time_zone}`,
  `Duration{time_unit}`, `Enum{categories}`, `Categorical{}`, or the object
  form of any scalar (`{"type": "Int64"}`).
- `Writer` (`_file_ops.py`) — context manager over a target `Path` and an
  optional `mark_self_write: Callable[[Path], None]`. `write_text`/
  `write_bytes` buffer a pending payload (last call wins); `__exit__`
  commits atomically only on a clean exit with a non-`None` payload, firing
  `mark_self_write` *before* the rename.

## Control flow

### `read_source(path, *, profile, columns, validate_columns, schema_overrides)` (`_io.py`)

1. `_validate_source_path` — reject URL-shaped or `..`-containing paths.
2. Normalise `profile`/`columns`/`validate_columns`/`schema_overrides`.
3. `_source_format` — extension dispatch to `SourceFormat`; unsupported
   extension raises `ValueError`.
4. Per format:
   - **CSV**: `_validate_csv_declared_schema_for_profile` (reads only the
     header row, not the whole file) checks declared-schema/projection/
     validate-columns membership against the header, and — for a bounded
     profile — that every required column has a declared dtype. Then
     `pl.scan_csv` (with `schema_overrides`/`infer_schema=False` when
     bounded), then `_validate_declared_schema` against the *scanned*
     schema (belt-and-braces beyond the header-only check), then
     `_select_columns`.
   - **JSON**: profile check first (`BoundedMemoryUnsupportedError` if not
     `preview_eager`/`deploy_live`), then eager `pl.read_json(...).lazy()`,
     `_validate_declared_schema`, `_select_columns`.
   - **NDJSON**: `pl.scan_ndjson` (columns existence pre-checked via
     `_validate_declared_columns_exist` when overrides are given, so a
     declared-but-absent column fails before the scan is built with
     overrides applied), `_validate_declared_schema`, `_select_columns`.
   - **Parquet**: `pl.scan_parquet`, `_validate_declared_schema`,
     `_select_columns`.

### `build_data_source_adapter(config)` / `read_data_source(config, ...)` (`_io.py`)

Branches on `config["sourceType"]` (`"flat_file"` default): `flat_file`
closes over `path`/`schema_overrides` and calls `read_source`; `databricks`
closes over `table` and lazily imports
`haute._databricks_io.read_cached_table`, applying `_select_columns` to its
result. Any other `sourceType` raises `ValueError` naming the two supported
values.

### `read_polars_input(config, *, profile)` (`_polars_io_registry.py`)

1. `format_for_config` → `resolve_input_mode` → `input_callable_key` (owner,
   callable name).
2. `validate_arguments` — allow-list check against
   `_polars_io_arguments.json`, decoding any `_DTYPE_MAPPING_ARGUMENTS`
   value through `parse_schema_mapping`.
3. If the profile is bounded (`_is_bounded_profile`): reject `mode="read"`
   on a non-inline source when a scanner exists (must use `scan`), reject
   `mode="read"` when the format has no scan surface and isn't
   `bounded_read`, and require a `"schema"` argument when
   `needs_schema_when_bounded`.
4. `_require_engines` — `importlib.util.find_spec` against `read_engines`;
   none importable raises `PolarsIoConfigError` before the call.
5. `_resolve_input_source` builds the leading positional argument(s) from
   node fields (`path` for `"path"`/`"inline"` kinds via `_validate_source_path`
   — imported from `_io` — for path kind, `(query, uri)` for database).
6. Call `getattr(pl, callable_name)(*source_args, **arguments)`;
   `ImportError`/`ModuleNotFoundError` is re-wrapped as
   `PolarsIoConfigError` naming the missing candidates. A `DataFrame`
   result is wrapped `.lazy()`; anything else raises `PolarsIoConfigError`
   ("not a single-table input").

### `write_polars_output(lf, config, *, resolved_path, profile)` (`_polars_io_registry.py`)

Mirrors the input path: `format_for_config` → `resolve_output_mode` →
`output_callable_key` → `validate_arguments` → `_resolve_output_target` →
`_require_engines`. Database targets always materialise via
`haute._polars_utils.streaming_collect` then `df.write_database(...)`.
Path targets require a caller-`resolved_path` (path resolution is the
caller's job, not this function's); `mode="sink"` calls the `LazyFrame`
sinker and returns `None`, `mode="write"` streaming-collects then calls the
`DataFrame` writer and returns `df.height`.

### Sidecar config entry points (`_polars_io_registry.py`)

- `anchor_config_source_path(config, base_dir)` — rewrites a relative
  `path` in a config copy to be anchored under `base_dir` (the pipeline
  directory), leaving non-path source kinds untouched.
- `read_polars_input_from_config(config_path, *, base_dir, profile)` —
  `haute._config_io.load_node_config` loads the sidecar JSON (relative
  `config_path` resolves against `base_dir`), anchors its `path`, then
  calls `read_polars_input`. This is what generated pipeline bodies call —
  see codegen.
- `write_polars_output_from_config(df, config_path, *, base_dir)` —
  same config load, then for a non-database target: resolves the output
  `path` against `base_dir` if relative, **creates the parent directory**
  (`mkdir(parents=True, exist_ok=True)` — the one place in this component
  that does auto-create a directory), then calls `write_polars_output`.

### `resolve_runtime_file_path(raw_path, *, source_file, pipeline_dir, project_root, prefer, enforce_project_root)` (`_path_resolution.py`)

1. `_infer_project_root` — explicit `project_root` wins; else infer from
   `source_file` (if absolute and outside `cwd`, its parent; otherwise
   `cwd`).
2. `_normalise_path_text` the raw path (backslash → forward slash, reject
   embedded NUL).
3. Absolute `raw_path` returns immediately (after an `enforce_project_root`
   check); relative paths build two candidates — `root / raw` (project) and
   `pipeline_dir / raw` or `source_file`'s resolved parent `/ raw`
   (pipeline) — each filtered through `_candidate_if_allowed` (drops a
   candidate that resolves outside `root` when `enforce_project_root`).
4. Order the two candidates by `prefer` (`"project"` default puts the
   project candidate first), de-duplicate, return the first that
   `.exists()`; if none exist, return the first candidate; if there are no
   candidates at all, raise `ValueError`.

### `discover_pipelines(root, *, strict)` (`discovery.py`)

1. `_configured_pipeline(root)` reads `haute.toml`'s `[project].pipeline`
   (logging — not raising — if the TOML is missing, unreadable, or
   malformed) and returns `root / <configured path>` unconditionally,
   without checking that the file exists or that its content matches;
   `discover_pipelines` itself then checks `configured.exists()` and that
   `haute.Pipeline` appears in its text before accepting it.
2. Independently scans `sorted(root.glob("*.py"))`, skipping `_SKIP` names and
   anything already matched in step 1, appending any file containing
   `haute.Pipeline`.
3. `strict=True` converts an `OSError` while reading a candidate file into
   a raised `ConfigError` instead of a logged-and-skipped warning.

### Atomic writes (`_file_ops.py`, `_polars_utils.py`)

- `atomic_write_bytes(path, data)`: write to `_temp_path_for(path)` (a
  sibling `{name}.{pid}.{uuid4}.tmp`), `tmp.replace(path)`; on any
  `BaseException` during either step, `tmp.unlink(missing_ok=True)` then
  re-raise. The parent directory is never created.
- `Writer.__exit__`: no-op if an exception is propagating or nothing was
  written; otherwise calls `mark_self_write(path)` (if given) then
  `atomic_write_bytes`.
- `_polars_utils.atomic_write(dest)` (a `@contextmanager`, distinct
  implementation from `_file_ops`): does `dest.parent.mkdir(parents=True,
  exist_ok=True)` unconditionally, yields a `dest.with_suffix(".parquet.tmp")`
  path, `tmp.replace(dest)` on clean exit, `tmp.unlink(missing_ok=True)` +
  re-raise on exception.
- `_write_atomically_if_possible(path, writer)`: calls `writer` through
  `atomic_write` only if `path.parent` already exists; otherwise calls
  `writer(path)` directly with no atomicity and no directory creation, so a
  missing parent directory surfaces as whatever error the underlying
  `write_*`/`sink_*` call raises rather than a silent `mkdir`.
  > NOTE: because `atomic_write`'s own `mkdir(..., exist_ok=True)` is only
  > ever reached when the parent already exists (the `path.parent.exists()`
  > gate upstream), that `mkdir` call is effectively dead code in this call
  > path — the net behaviour (never auto-create a missing parent) matches
  > `_file_ops`'s stated invariant, just via a different mechanism.
  > NOTE: unlike `_file_ops._temp_path_for`, `_polars_utils.atomic_write`
  > derives the same `dest.with_suffix(".parquet.tmp")` path for every writer.
  > Concurrent calls targeting the same destination can overwrite, move, or
  > remove one another's staging file (and on POSIX a rename can expose an
  > inode another writer still has open). The helper is atomic only under its
  > implicit single-writer-per-destination precondition.

### Streaming collect/sink (`_polars_utils.py`)

- `streaming_collect(lf, *, profile, allow_broad, execution_context)`:
  resolves the effective profile from an active `ExecutionContext` when one
  exists — **the passed `profile` argument is a fallback only, overridden
  by any active context's profile.** `allow_broad=True` is rejected unless
  the effective profile is in `_BROAD_COLLECT_PROFILES` (`PREVIEW_EAGER`
  only). Calls `lf.collect(engine="streaming")`; on a Polars streaming-
  compatibility error (message contains `"stream"`, see `_is_streaming_
  compatibility_error`) with `allow_broad=False`, wraps as
  `BoundedMemoryUnsupportedError`; with `allow_broad=True`, logs and falls
  back to `lf.collect()`. A `_POLARS_STREAMING_ERRORS`-typed exception whose
  message does *not* look streaming-related re-raises unchanged.
- `bounded_collect_batches(lf, *, profile, chunk_size, ...)`: same
  streaming-error mapping, applied around `lf.collect_batches(...,
  engine="streaming")` construction and each `next()` call; inserts
  `execution_context` checkpoints between batches when a context is active.
- `bounded_sink`/`streaming_sink`: `sink_csv`/`sink_parquet` via
  `_streaming_sink_to_path`, wrapped in `temporary_streaming_chunk_size`;
  a streaming-incompatibility error maps to `BoundedMemoryUnsupportedError`
  with no collect fallback.
- `best_effort_sink`/`safe_sink`: same streaming attempt, but on a
  `_POLARS_STREAMING_ERRORS` failure falls back to
  `streaming_collect(..., profile=<active context's profile or LAZY_SINK>)`
  then an eager `write_csv`/`write_parquet`. `best_effort_sink` requires its
  caller to pass `allow_broad=True` or raises `ValueError` immediately — no
  accidental fallback path. `safe_sink(lf, path, *, fmt, fast_checkpoint)`
  has no `allow_broad` parameter of its own; it is a fixed wrapper that
  always calls `best_effort_sink(..., allow_broad=True)`, so it can never
  raise that `ValueError`.
- `temporary_streaming_chunk_size(chunk_size)`: `_STREAMING_CHUNK_SIZE_LOCK`
  (a module-level `threading.RLock`) serialises save/set/restore of
  Polars' process-global streaming chunk size config, since Polars exposes
  it as global mutable state rather than a per-call parameter.

## Edge cases and invariants

- `_normalise_columns` rejects a bare `str`/`bytes` passed where an
  iterable of column names is expected (the classic "iterated my string
  into one-char columns" footgun), and de-duplicates while preserving
  first-seen order.
- `_select_columns` always projects using the *schema's* column order
  filtered to the requested set, never the caller-requested tuple's order.
- CSV header parsing (`_csv_header_columns`) opens with
  `encoding="utf-8-sig", errors="replace"` and reads only the first row via
  `csv.reader` — an empty file raises `SchemaMismatchError` (no header
  row), and a header with duplicate column names raises
  `SchemaMismatchError` naming the duplicates, both before any scan is
  built.
- `load_external_object`'s `functools.lru_cache(maxsize=32)` keys on
  `(path, digest, file_type, model_class)` where `digest` is
  `content_hash(Path(path))` (recomputed, not cached, on every call) — a
  changed file is never served stale because its digest changes the cache
  key, but the 32-entry LRU bound means a 33rd distinct combination evicts
  the least-recently-used entry and forces a re-parse.
- `_validate_source_path` is defined once in `_io.py` and imported into
  `_polars_io_registry.py` (`_resolve_input_source`) rather than
  duplicated, so the URL/`..` guard is identical across both the legacy and
  registry read paths. `_normalise_profile` and `_is_bounded_*` helpers,
  by contrast, are each defined separately in `_io.py` and
  `_polars_io_registry.py` with the same shape but no shared implementation.
- `resolve_input_mode`/`resolve_output_mode` eagerly validate the
  *default* mode's availability too (calling `input_callable_key`/
  `output_callable_key` even when the config didn't specify a mode), so a
  format with no read/write surface at all fails at config-resolution time,
  not when the invocation is attempted.
- `allowed_arguments` subtracts, in order: underscore-prefixed names,
  `REMOTE_IO_ARGUMENTS`, `_OBJECT_VALUED_ARGUMENTS`, the format's own
  `source_owned_args`, and (only for callables named `sink_*`)
  `_SINK_EXECUTION_OWNED`.
- `missing_engines(engines)` returns `[]` (i.e. "not missing") the moment
  *any one* of the listed import names resolves via
  `importlib.util.find_spec` — the engines tuple is an OR-list of
  alternatives, not a required set.
- `_path_resolution._normalise_path_text` rejects an embedded NUL byte
  (`\x00`) with `ValueError` before any `Path` construction, since NUL is
  invalid in filesystem paths on every supported OS and would otherwise
  surface as a confusing OS-level error later.
- `_path_case_audit._warned` is a process-lifetime, path-keyed cache of
  *positive* findings only — a path that comes back clean is re-scanned on
  every call (so a twin introduced later is still caught), but a path that
  already warned once is never logged again in that process.
- `case_equivalent_siblings` walks ancestors only when `stop` is given and
  *path* is actually under it; otherwise only the final path segment is
  checked (walking above `stop` — e.g. into `$HOME` or `/` — would be
  wasted work and noise).
- On Windows, `atomic_write_bytes`'s `tmp.replace(path)` can raise
  `PermissionError`/`ERROR_SHARING_VIOLATION` if another process holds
  `path` open without `FILE_SHARE_DELETE` (the default for Python's
  `open()`/`read_bytes`/`read_text`). This is a deliberate fail-loud miss —
  not retried — under the single-user trust model; see the `_file_ops.py`
  module docstring and `tests/test_file_ops.py::TestAtomicWriteWindowsReaderContention`.
- Concurrent `atomic_write_bytes` calls are isolated by pid/UUID temp names and
  remain last-rename-wins. `_polars_utils.atomic_write` and the profiled sink
  family do not have that isolation: their fixed `.parquet.tmp` path requires
  external serialisation for same-destination concurrent writes.
- `_malloc_trim` is platform-conditional: `ctypes.CDLL("libc.so.6").
  malloc_trim(0)` on Linux, `kernel32.HeapCompact` (with an explicit
  `HANDLE` return-type declaration to avoid 64-bit pointer truncation) on
  Windows, and a documented no-op on macOS (callers should `gc.collect()`
  instead). Failures on either platform are caught and logged at `debug`,
  never raised.

## Error handling

| Situation | Exception | Where it surfaces |
|---|---|---|
| Unsupported file extension | `ValueError` | `_io._source_format`, before any read. |
| URL-shaped or `..`-containing path | `ValueError` | `_io._validate_source_path`, called from both `read_source` and the registry's `_resolve_input_source`. |
| Bare `str`/`bytes` passed as a columns iterable | `ValueError` | `_io._normalise_columns`. |
| Empty/duplicate-header/missing CSV columns | `SchemaMismatchError` | `_io._csv_header_columns` / `_validate_csv_declared_schema_for_profile`, before `scan_csv` is built. |
| Declared schema mismatch (missing column or dtype disagreement) | `SchemaMismatchError` | `_io._validate_declared_schema` (all formats); `_polars_dtypes.parse_dtype`/`parse_schema_mapping` for a malformed dtype spec. |
| Plain JSON / CSV without full dtypes in a bounded profile | `BoundedMemoryUnsupportedError` | `_io.read_source`, before parsing. |
| Eager mode, no scan surface, or missing required `schema` in a bounded profile | `BoundedMemoryUnsupportedError` | `_polars_io_registry.read_polars_input`, before the polars call. |
| Streaming collect/sink incompatibility (no broadening allowed) | `BoundedMemoryUnsupportedError` | `_polars_utils.streaming_collect`, `bounded_collect_batches`, `bounded_sink`. |
| Unknown format / mode / argument / missing engine / non-table result | `PolarsIoConfigError` (`ValueError` subclass) | `_polars_io_registry` — `format_for_config`, `resolve_input_mode`/`resolve_output_mode`, `validate_arguments`, `_require_engines`, `read_polars_input`. |
| Missing engine package surfaced only at call time (`ImportError`) | Re-wrapped `PolarsIoConfigError` | `read_polars_input`/`write_polars_output`'s `except (ImportError, ModuleNotFoundError)`. |
| Unknown polars I/O callable key | `KeyError` | `_polars_io_schema.io_function`, listing known keys. |
| `best_effort_sink` called without `allow_broad=True` | `ValueError` | `_polars_utils.best_effort_sink`, before any I/O. `safe_sink` has no `allow_broad` parameter and always calls `best_effort_sink` with `allow_broad=True`, so it can never hit this error. |
| `streaming_collect(allow_broad=True)` for a non-`PREVIEW_EAGER` profile | `ValueError` | `_polars_utils.streaming_collect`. |
| Unreadable candidate file during pipeline discovery | Logged warning (default) or `ConfigError` (`strict=True`) | `discovery.discover_pipelines`. |
| No valid path candidate at all | `ValueError` | `_path_resolution.resolve_runtime_file_path`. |
| Embedded NUL byte in a path | `ValueError` | `_path_resolution._normalise_path_text`. |
| Windows atomic-write rename blocked by a reader | `PermissionError` (propagated, not wrapped) | `_file_ops.atomic_write_bytes`. |

All `SchemaMismatchError`/`BoundedMemoryUnsupportedError` instances are
`HauteError` subclasses and carry structured `context` kwargs (path,
column names, profile, missing/mismatch lists) rendered into `str(err)`;
`PolarsIoConfigError` and the plain `ValueError`s raised directly in this
component are not `HauteError` subclasses.

## Testing

Tests live across several files, split roughly by module:

- `tests/test_io.py` — `read_source` for every format (Parquet, CSV
  including inference-vs-declared-dtype and bounded-profile rejection,
  JSON eager-only enforcement, JSONL), projection/schema validation
  (`selected_columns` missing, `schema_overrides` missing/mismatched),
  case-insensitive-filesystem behaviour, path-traversal rejection,
  `load_external_object` for JSON/pickle/joblib/CatBoost including the
  `functools.lru_cache` behaviour (same digest → single load; different
  digest or `model_class` → separate cache entries) and the unsupported-
  `file_type` error, and `DataSourceAdapter` for both `flat_file` and
  `databricks` source types plus its config-validation errors.
- `tests/test_polars_io_registry.py` — `TestRegistrySchemaCompleteness`
  (every format's reader/scanner/writer/sinker actually resolves against
  the extracted schema), `TestDtypeCodec` (round-trip `parse_dtype`/
  `dtype_to_spec` over the documented grammar), `TestReadPolarsInput`/
  `TestWritePolarsOutput` (mode resolution, bounded-profile rejection,
  argument allow-listing, engine-missing errors).
- `tests/test_polars_io_interface_contracts.py` —
  `TestCommittedSchemaMatchesInstalledPolars` (re-extracts the schema from
  the installed polars and diffs against the committed JSON — the drift
  contract), `TestCommittedSchemaInvariants` (structural sanity of the
  committed file itself), `TestSchemaLoaderHelpers` (`io_function`/
  `argument_names` behaviour including the unknown-key error).
- `tests/test_json_read_documented.py` — documents/pins the JSON-is-eager,
  NDJSON-uses-scan_ndjson, Parquet-has-an-escape-hatch behaviours
  specifically (`TestDocstringDocumentsLimitation`,
  `TestNDJSONUsesScanNDJSON`, `TestPlainJSONIsEager`,
  `TestParquetEscapeHatchExists`).
- `tests/test_data_io_nodes.py` / `tests/test_data_io_roundtrips.py` —
  integration-level coverage of `dataInput`/`dataOutput` node execution end
  to end (sink execution, output-path resolution, codegen/parse

Known coverage gaps: the streaming-error classification helpers
(`_is_streaming_compatibility_error`/`_is_streaming_sink_error`) rely on a
string-matching heuristic (`"stream" in str(exc).lower()`) to distinguish
a genuine streaming-incompatibility `ComputeError`/`InvalidOperationError`/
`SchemaError` from an unrelated Polars error of the same exception type;
the test suite exercises both branches but does not exhaustively probe
every Polars error message shape that could hit this heuristic.

No test exercises two concurrent `_polars_utils.atomic_write`/profiled-sink
calls to the same destination. The fixed temp path makes that unsupported in
the current implementation; only `_file_ops`'s unique-temp concurrent-writer
contract is directly tested.
